## 背景

dsh 插件是 Cordis 进程内插件（npm 包声明 `dsh.bundle.patch`，用 `dsh plugin --profile <name> add <pkg>` 装进 `$DSH_HOME/profiles/<name>`），只能在 dsh 进程里生效；dsh 的 SDK/ACP 协议都只提供 `session/prompt`，没有 MCP server 模式。tds 各 runtime 共用的能力通道是可授权工具（`AGENT_CONFIGURABLE_TOOLS`，pi 直接注册，外部 runtime 经 `tds mcp-bridge`，omp 经 `bridgeTools`）。

目标：新增可授权工具 `dsh`——agent 把一个子任务委派给本机 dsh 的 headless 模式（`dsh --profile headless --json`），子任务在同一工作区、全权限、无审批下运行，返回最终答复。它跑在 tds 自己的 dsh home（`~/.tds/dsh-home`，`dshHome()`）的 `headless` profile 上，机器主人用 `DSH_HOME=~/.tds/dsh-home dsh plugin --profile headless add <package>` 装的插件全部生效（已在临时 home 验证：该命令会从模板初始化 headless profile，`--patch` 覆盖层能正常叠加到 headless profile 上）。

**apps/executor/src/lib/dsh/subtask.ts（新文件）**
- `dshSubtaskSchema()`：name `dsh`，label `Delegate to dsh`，description 说明：在本机 DeepSeek Harness 上以独立 agent 运行一个自包含子任务，同一工作区、全权限、不会反问；装在 tds dsh home 里的 dsh 插件可用，任务里点名要用的插件/能力；返回最终答复，它改的文件要自己 `git diff` 核对；用上一次结果里的 `session_id` 继续同一会话。parameters：`task`（string，必填）、`session_id`（string，可选）。
- `makeDshTool(cwd, step: Pick<ModelMachineStep, 'stepId' | 'secretEnv' | 'readOnly' | 'runtime' | 'agent'>)`，execute：
  1. `resolveDshExecutable()` 为空 → `text(DSH_MISSING)`；`signIn({ ...process.env, ...step.secretEnv })` 为空 → `text(DSH_NOT_SIGNED_IN)`（复用 `dsh/bin.ts`、`dsh/home.ts`，`text` 来自 `remoteTools.ts`）。
  2. `subtaskModel(login, step)`：`step.runtime === 'dsh'` 时用 `step.agent.modelId` 按 `/` 拆成 provider/model、`step.agent.thinkingLevel` 作 reasoningEffort，先过 `unreachedModel` 不可达则返回其文本；否则 `{ provider: login.apiKey ? 'deepseek-official' : 'deepseek-account', model: 'deepseek-v4-flash' }`。
  3. `stagePatch(dshHome(), \`${stepId}-dsh-${n}\`, { instructions: SUBTASK_NOTE, model })`，`n` 为进程内计数；`SUBTASK_NOTE`：你在替另一个 agent 执行它委派的子任务，工作区就是当前目录，没有人回答提问，做不了的事和需要决定的事写进最终答复。
  4. `spawn(bin, ['--profile', 'headless', '--patch', patch, '--json', ...(session_id ? ['--session-id', session_id] : []), '-'], { cwd, env: dshEnv(home, { secrets: step.secretEnv, readOnly: step.readOnly }) })`——启动器 flag 在前、应用 flag 在后；任务写入 stdin 后关闭（`-` 读 stdin，避免 argv 长度和引号问题）。
  5. 逐行解析 stdout NDJSON（事件名已核对 dsh-headless 源码）：`session.sessionId`；`tool_call.tool` 计数并 `console.log('[dsh] tool ' + tool)`；`status.phase === 'turn_end'` 取 `reason`；`final.text`；`error.message`。stderr 保留末尾 20 行。
  6. 退出码 0 → 答复 = `final.text`（超过 60_000 字符截尾并前置说明）+ 尾注 `[dsh session <id>, <n> tool calls — pass session_id to continue it]`；非 0 → `dsh sub-task failed (<reason 或 error.message 或 stderr 末尾>)` 加上已收到的 final 文本。
  7. `signal` abort → `killTree(child)`，返回 `dsh sub-task cancelled`；总时长超过 `TIMEOUTS_MS.dshSubtask` → `killTree`，返回超时说明加已收到的文本。`waitForExit` 与 `killTree` 来自 `childProcess.ts`；finally `unstagePatch(patch)`。

## 边界情况

- 老版本 executor 收到 `step.tools` 里的 `dsh`：pi 的白名单按名过滤、无对应工具即忽略，bridge 的 `LOCAL_BRIDGED` 不含它则不提供——与 `push_branch` 加入时相同，不设 CLI 版本门槛（subtask.ts）。
- `session_id` 不存在或属于别的 cwd：CLI 退出 1 并在 stdout 写 `error` 事件，工具按失败文本返回，模型改为新开会话（subtask.ts 第 6 步）。
- headless 没有 ask_user 一类工具，子任务无法反问：SUBTASK_NOTE 要求把待决事项写进答复（subtask.ts 第 3 步）。
- 同一回合多次调用：patch 文件按计数命名互不覆盖；会话文件落在 `~/.tds/dsh-home/sessions/<projectKey(cwd)>/` 下，与 acp 回合的会话并列。
- `step.readOnly` 回合本就不暴露该工具（GRANTED_LOCAL_TOOLS 只在产出回合），`dshEnv` 的 readOnly 透传只是防御。

## 假设

- 工具名 `dsh`，曝光范围与 `remote_shell`/`push_branch` 相同（implement-track 产出回合）。
- 子任务模型：agent 本身是 dsh runtime 时沿用其模型与档位；否则按登录路线取 `deepseek-v4-flash`（本机 ACP 模型选择器的默认项；`deepseek-account` 路线下该名未验证，不可用时 CLI 的报错会原样出现在工具结果里）。
- 子任务会话保留在 tds 的 dsh home 下，不清理也不镜像到 R2；子任务不接入平台工具和团队 MCP。
- 超出范围：把插件装进 dsh runtime 自己的 acp profile、在平台 UI 管理 dsh 插件、把插件工具桥成 MCP。
